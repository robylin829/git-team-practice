# 05｜教師／助教帶課手冊

## 對象、成果與必要條件

對象是零程式基礎的大學生，不要求程式語言、前端框架或開發經驗。以純文字降低門檻，課程重點是版本控制與實際 GitHub 協作。

**GitHub 為必做項目。** 每位學生都需有自己的 repo、feature branch、已推送歷史、PR，以及另一人的 Review；只在本機 merge 不能替代。每位學生同時擔任作者與審查者。單人學生由教師／助教審查。

備課檢查：Windows＋PowerShell 7、Git 2.28 以上、GitHub CLI、能連線 GitHub、可安裝軟體、可登入與收取驗證信。校園代理／防火牆可能影響登入及 push，請課前測試。

## 發放方式

將完整教材 ZIP 發到課程平台。學生解壓縮後從 git init 開始；不要發一個已含 .git 的資料夾。也可由教師先把這份資料夾上傳自己的 GitHub 作為教材庫，再請學生 **Download ZIP**，避免 clone 帶入教師的 origin。

若教師要首次發布教材（在自己的乾淨教材副本、且已登入 gh）：

```powershell
git init -b main
$teacherLabName = Read-Host '輸入你的 Commit 署名'
$teacherLabEmail = Read-Host '貼上你自己的 GitHub noreply 信箱'
git config user.name "$teacherLabName"
git config user.email "$teacherLabEmail"
git add -- .
git diff --staged --stat
git commit -m 'docs(course): 發布零基礎 GitHub 協作練習教材'
$teacherRepoName = Read-Host '輸入尚未使用的教材 repo 名稱'
gh repo create "$teacherRepoName" --private --source . --remote origin --push
gh repo view --web
```

私有教材 repo 需要學生可讀權限。是否改為公開，由教師依教材授權及課程需要決定；本包不預設代為發布。學生練習庫一律先用 Private，並邀請同組同學與驗收教師。

## 建議教學節奏：兩次各 90 分鐘

| 時間 | 活動 | 當場確認 |
| --- | --- | --- |
| 第一次 0～15 分 | Git 與 GitHub、終端機、三個位置 | 每人能用自己的話說明 commit 不等於 push |
| 15～35 分 | 第 1～2 關：init、commit、建 GitHub repo | 每人網頁真的看見 Private repo，邀請同學 |
| 35～55 分 | 第 3～4 關：分支、Atomic Commit、暫存區 | 比對 HEAD todo／staged doing／工作檔 BROKEN |
| 55～75 分 | 第 5～6 關：restore、推送錯誤、revert | GitHub 曾出現 BROKEN，後回到 todo，保留歷史 |
| 75～90 分 | 第 7 關：開 PR | 每人一個 Open PR，base/head 正確 |
| 第二次 0～15 分 | 回顧並檢查邀請 | 所有人可讀取同學私有 repo |
| 15～45 分 | 各自 clone 同學 repo、驗證、Review | 每人都留下具體 Review |
| 45～65 分 | 視 Review 修正並重新確認 | 同一 PR 新增修正，不另開 PR |
| 65～80 分 | 合併、同步 main | Merged、todo、說明檔、clean |
| 80～90 分 | 繳交與反思 | repo／PR／Review／SHA 證據完整 |

安裝與註冊另留約 20～40 分鐘；建議課前完成。網路、班級規模與學生熟悉度會影響速度。

## 評分規準（100 分）

| 項目 | 分數 | 可檢查證據 |
| --- | --- | --- |
| 自己建立與推送 GitHub repo | 15 | 私有庫可讀、main 基準與本人署名 |
| 分支與單一目的 Commit | 15 | feat/task-status、說明檔 Commit 有 Why |
| 暫存區與 restore | 15 | staged／工作檔差異、取消暫存保留內容、restore 不增 Commit |
| 已推送錯誤與 revert | 15 | BROKEN 與 Revert 皆存在，最後 todo |
| PR 的說明與驗證 | 15 | 問題／結果／實測，base/head 正確 |
| 對同學的 Review | 15 | 由不同帳號送出，有重現與結果／建議 |
| 合併、同步與個人反思 | 10 | Merged、main clean、繳交表完整 |

不以安裝速度或英文熟練度評分。不能只看綠色勾勾；本教材沒有自動測試工作流，diff --check 只是格式檢查。

## 常見帶課提醒

- 第 2 關確認 repo 是學生自己的，不是教師的教材庫。
- 在第 2 關就完成協作者邀請；PR 作者無法核准自己的 PR。
- 第 4 關先取消暫存、備份，再 restore；用這一關解釋三個位置。
- 第 6 關務必先 push BROKEN 並查看網頁，才 revert，再 push 修復。
- PR 的最終 Files changed 主要是說明檔；錯誤與修復互相抵銷，需到 Commits 看歷史。
- repo 設定允許 **Allow merge commits**；以 Create a merge commit 合併，保留練習歷史。若班級平台限制合併方式，先調整驗收方式與教學說明。
- 同儕核准是本課的人工檢核；新建私人 repo 未必自動有保護規則，不能假設 GitHub 會阻止未審先合併。
- 修正建議應具體，但不要硬性要求每份正確成果都製造額外錯誤。
- 任何需刪除的本機檔案先移垃圾桶；不使用刪 .git 或強制推送作為重做捷徑。
- 共用電腦請依校方程序登出 GitHub CLI 與瀏覽器；不要讓下一位同學沿用前一人的帳號。

## 延伸練習（完成必修後再選）

讓學生從已同步 main 建立新分支 `docs/report-checklist`，新增一份小組報告驗收清單，再跑一次 add → diff → commit → push → PR → Review → merge → pull。這次自行選定 Commit 原因、PR 標題與驗證步驟，不照抄既有答案。

本次先不引入合併衝突、rebase、fork 或 GitHub Actions，避免在完成第一個協作循環前增加工具負擔。
