# 02｜雙人協作：互相審查真正的 GitHub PR

兩人一組，A、B 各自完成學生手冊第 1～7 關，再交叉 Review：A 審 B，B 審 A。兩個人都要當作者和審查者，不能只共用一個帳號操作。

## 1. 作者邀請協作者

在學生手冊第 2 關後執行：

1. 作者到自己 GitHub repo → Settings → Collaborators（介面有時顯示 Collaborators and teams）。
2. 選 Add people，輸入同學的 GitHub 使用者名稱，核對帳號後送出邀請。
3. 同學在自己的 GitHub 通知／邀請信中接受；必要時到作者提供的 repo 網址查看邀請。
4. 同學用自己的帳號打開作者的私有 repo，確認能讀 README。
5. 交換角色，另一位作者也要邀請自己。教師如需驗收私有庫，同樣邀請教師指定帳號。

不要把儲存庫改 Public 來處理權限問題，也不要交換登入密碼。

## 2. 審查者下載對方的專案

前置：對方已完成第 7 關並給你 PR 網址；你已接受協作者邀請。
使用自己的 GitHub 帳號，在自己的終端機操作。保留原本專案位置，並把同學的 clone 放在旁邊的新資料夾。

```powershell
gh auth status
git status --short
$labAuthorPath = (Get-Location).Path
Set-Location ..
$labPeerUrl = Read-Host '貼上同學 repo 的 Code / HTTPS 複製網址，例如 https://github.com/帳號/儲存庫.git'
$labPeerFolder = Read-Host '輸入尚未存在的資料夾名稱，例如 peer-review-01'
Test-Path -LiteralPath $labPeerFolder
```

**最後一行必須為 False。** 若 True，重新設定 `$labPeerFolder` 為新名稱，不要刪掉舊資料夾。

```powershell
git clone "$labPeerUrl" "$labPeerFolder"
Set-Location -LiteralPath $labPeerFolder
git remote -v
gh pr list
gh pr checkout feat/task-status
git branch --show-current
git fetch origin
git diff origin/main...HEAD
Get-Content -LiteralPath task-status.txt
Get-Content -LiteralPath status-guide.txt
git log -4 --oneline
git diff --check origin/main...HEAD
$LASTEXITCODE
git status --short
```

**驗收：**origin 指向同學的 repo；分支為 feat/task-status；狀態 todo，三種定義完整；可見 BROKEN 與 Revert 兩筆紀錄；diff --check 退出碼 0；無未提交變更。

`clone` 會下載完整 Git 歷史並設定 origin；這裡不用再 `git init` 或 `gh repo create`。

## 3. 留下有內容的 Review

審查至少包含：

- 觀察：哪個檔案改了什麼？用語是否清楚？
- 重現：你實際跑了哪個指令？
- 結果或建議：實際輸出為何？若有問題，如何改善？

```powershell
gh pr view feat/task-status --web
```

在 GitHub：Files changed → 閱讀新增的狀態說明 → 需要指出特定行時點行號旁的 `+` → 輸入具體建議 → Start a review → Review changes。

- 有問題：選 Request changes，說明需要修正的地方。
- 實測符合要求：選 Approve，填入你的驗證結果，再 Submit review。
- 只是提問或課堂尚未決定是否通過：選 Comment。

可參考以下文字，但必須改成自己的實測內容，不要未測就貼：

> 我讀了 status-guide.txt，三種狀態都有說明。執行 Get-Content task-status.txt 得到 todo，git log 看到錯誤與 Revert，git diff --check origin/main...HEAD 退出碼為 0。建議保留 done 需要同學確認的定義，才能避免各自認定完成。

若偏好指令送出正式 Review，可在實測成功後執行；網頁和指令二選一即可。

```powershell
New-Item -ItemType Directory -Path .lab-evidence -Force | Out-Null
$labReviewText = Read-Host '輸入你自己的觀察、實測指令與結果'
Set-Content -LiteralPath .lab-evidence/review.txt -Value $labReviewText -Encoding utf8
gh pr review feat/task-status --approve --body-file .lab-evidence/review.txt
```

若有需修正的問題，將最後一行改為：

```powershell
gh pr review feat/task-status --request-changes --body-file .lab-evidence/review.txt
```

**不能核准自己發出的 PR。** 作者與審查者必須是不同 GitHub 帳號。單人練習可請教師或助教擔任審查者。

## 4. 作者回覆與修正（有建議時才做）

作者回到自己的專案。若你剛剛完成審查，可以用原終端機保存的路徑回去：

```powershell
Set-Location -LiteralPath $labAuthorPath
git remote -v
git switch feat/task-status
git status --short
```

確認 origin 是**自己的** repo。以下只是「同學請你補 done 的確認條件」的修正範例；請依實際 Review 修改，不必每人強制做相同改動。不要重複執行而一直新增相同句子。

```powershell
Add-Content -LiteralPath status-guide.txt -Value '完成確認：由另一位組員檢查成果後，才標記 done。' -Encoding utf8
git diff -- status-guide.txt
git add -- status-guide.txt
git diff --staged -- status-guide.txt
git commit -m 'docs(status): 補上完成確認方式以避免自行認定完成'
git push
gh pr view feat/task-status --web
```

到 PR 回覆對方「已補上哪一行、如何驗證」，必要時按 Re-request review。同一個 PR 會自動收到這個分支的新 Commit，不要另開第二個 PR。

## 5. 審查者重新確認

審查者切回**同學的 clone**（用檔案總管開該資料夾的 pwsh 也可以），先確認 origin：

```powershell
git remote -v
git status --short
git switch feat/task-status
git pull --ff-only origin feat/task-status
Get-Content -LiteralPath status-guide.txt
git diff --check origin/main...HEAD
$LASTEXITCODE
gh pr view feat/task-status --web
```

實測通過後，再送一則 Approve Review。作者接著回學生手冊第 8 關合併。

## 6. 離開同學專案

```powershell
Set-Location -LiteralPath $labAuthorPath
git remote -v
```

若關過終端機，`$labAuthorPath` 不存在，請從檔案總管重新開啟自己的專案，再核對 origin。

**共同驗收：**A 和 B 都有自己的 Merged PR；每人也在另一人的 PR 有一則實際 Review。保留同學的 clone 供驗收，不需刪除。
