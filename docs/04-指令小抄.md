# 04｜指令小抄：先看，再改，再送

此頁供查閱；第一次請照學生手冊順序操作，不要把整頁當腳本執行。

| 想做什麼 | 指令 | 會改動哪裡 |
| --- | --- | --- |
| 看目前資料夾 | Get-Location | 只讀 |
| 看檔案 | Get-Content task-status.txt | 只讀 |
| 建立 Git 歷史 | git init -b main | 本機 .git |
| 設本專案署名 | git config user.name '你的暱稱' | 本機專案設定 |
| 看狀態 | git status | 只讀 |
| 看工作目錄相對暫存區的差異 | git diff | 只讀，未追蹤檔不列入 |
| 把指定檔放進待提交籃子 | git add -- task-status.txt | 暫存區 |
| 看籃子相對 HEAD 的差異 | git diff --staged | 只讀 |
| 存一筆有原因的紀錄 | git commit -m '說明修改與原因' | 本機歷史 |
| 看最近五筆 | git log -5 --oneline | 只讀 |
| 看最新提交 | git show HEAD | 只讀 |
| 建立並切到新分支 | git switch -c feat/task-status | 本機分支 |
| 切到已有分支 | git switch main | 工作目錄與目前分支 |
| 看目前分支 | git branch --show-current | 只讀 |
| 看遠端網址 | git remote -v | 只讀 |
| 首次推送分支 | git push -u origin feat/task-status | GitHub 遠端分支 |
| 後續推送 | git push | GitHub 遠端分支 |
| 取回遠端分支資訊 | git fetch origin | 本機遠端追蹤資訊，不合併工作分支 |
| 下載並快轉目前分支 | git pull --ff-only origin main | 本機 main；只在 main 使用此例 |
| 複製另一個 repo | git clone HTTPS網址 新資料夾 | 新資料夾、完整 Git 歷史、origin |
| 取消暫存，保留工作內容 | git restore --staged -- task-status.txt | 暫存區 |
| 還原未暫存變更，先備份 | git restore -- task-status.txt | 工作目錄，會覆寫內容 |
| 撤銷最新普通提交 | git revert --no-edit HEAD | 新增反向 Commit，執行前核對 log |
| 看 GitHub 登入 | gh auth status | 只讀 |
| 開 repo 網頁 | gh repo view --web | 瀏覽器 |
| 列出 Open PR | gh pr list | 只讀 |
| 看 PR 網頁 | gh pr view feat/task-status --web | 瀏覽器 |
| 查空白格式問題 | git diff --check | 只讀；還要核對內容與退出碼 |

## 三種回復的差別

| 情境 | 做法 | 新增 Commit？ |
| --- | --- | --- |
| 已 add，只想先拿出籃子 | restore --staged | 否，檔案內容保留 |
| 檔案改壞但還未提交 | 備份後 restore 指定檔案 | 否，未暫存內容被覆寫 |
| 已 commit／push 的普通提交 | 確認 SHA 後 revert | 是，保留原始歷史 |

## 送出前四句自問

1. 我現在在哪個資料夾、哪個分支、哪個 origin？
2. staged diff 是否只有本次目的需要的檔案？
3. Commit 訊息是否能解釋為什麼要改？
4. 我實際如何驗證？同學能照著重現嗎？
