# 03｜出錯先看訊息，不要重貼整關

先保留錯誤畫面，確認目前資料夾與分支。這些是觀察指令，不會修改檔案：

```powershell
Get-Location
git status
git branch --show-current
git remote -v
git log -5 --oneline
gh auth status
```

若還沒有 `git init`，部分 Git 指令顯示 not a git repository 是正常的；先回到對應關卡。

| 現象 | 原因／檢查 | 做法 |
| --- | --- | --- |
| git／gh 無法辨識 | 未安裝或終端機未重新開啟 | 重新開 PowerShell 7，再查版本；仍失敗找助教 |
| PowerShell Major 是 5 | 開到 Windows PowerShell | 從開始功能表開 PowerShell 7 |
| not a git repository | 不在專案根目錄，或還未 init | 找到有 README、task-status.txt 的資料夾；已有 .git 時不要重新 init |
| Author identity unknown | 本專案署名尚未設定 | 重新做第 1 關的 git config user.name／user.email |
| nothing to commit | 沒有差異或已經提交 | git status、git log -1；不要為了產生訊息而亂改檔 |
| 普通 git diff 沒顯示新檔 | 新檔未追蹤 | Get-Content 先讀，再 add 指定檔，查看 diff --staged |
| git diff 空白但 status 有 M | 變更可能已暫存 | 查看 git diff --staged |
| restore 後仍是 BROKEN | 暫存區已存了 BROKEN | 先備份；restore --staged 取消暫存，再 restore 工作檔 |
| repository already exists | 自己帳號已有同名 repo | 檢查網頁；選全新名稱，不要刪庫重來 |
| remote origin already exists | 可能用 clone 教材或前次建庫已成功 | git remote -v 核對；不要重做 remote add 或隨便改別人的網址 |
| Permission denied／403 | 登入帳號錯誤或沒接受邀請 | gh auth status；私有庫先接受協作者邀請 |
| Repository not found／404 | 位址錯或私有庫無權限 | 在已登入的瀏覽器核對 repo；確認邀請已接受 |
| There is no upstream branch | 該分支未記住推送對象 | 在 feat/task-status 用 git push -u origin feat/task-status |
| 分支 already exists | 你之前已經建立過 | 改用 git switch feat/task-status，不再加 -c |
| git pull --ff-only 被拒絕 | 本機與遠端歷史已分岔 | 保存 status、log 與 diff，請助教確認；不要強制覆蓋 |
| PR 沒有可比較內容 | main 可能已含修改或選錯分支 | 檢查 base main、head feat/task-status，以及 Commits 頁面 |
| 無法 Approve | 可能正在審自己的 PR | 換同學自己的帳號審；不要交換登入 |
| PR 無法 Merge | 規則、權限或衝突阻擋 | 閱讀 GitHub 顯示原因，找教師確認 |
| diff --check 無輸出 | 通常代表沒有空白格式問題 | 緊接執行 $LASTEXITCODE，確認為 0；不代表所有內容都正確 |
| 終端機顯示冒號／END 不動 | Git 分頁器開啟 | 按 q 離開 |
| 顯示 >> 一直等輸入 | 引號、括號或多行文字未結束 | 按 Ctrl+C 中止未完成輸入，重新貼完整區塊 |
| 中文亂碼 | 終端機版本或讀取編碼問題 | 確認 pwsh 7；用 Get-Content -Encoding utf8 檢查 |
| LF will be replaced by CRLF | 換行提示，未必是錯誤 | 確認有 .gitattributes，閱讀 diff；不要因此改全機 Git 設定 |

## Push 被拒絕：先保存並觀察

不要直接使用強制推送。先確認 repo 與分支，再執行：

```powershell
git fetch origin
git status
git log --oneline --graph --all -10
git diff
git diff --staged
```

若只是落後、工作目錄乾淨且本機沒有自己的額外 Commit，可在確認分支後 `git pull --ff-only` 再 push；若已分岔或有未提交修改，交給助教看具體情況，不要盲目執行 merge／rebase。

## Revert 發生衝突

標準主線緊接著撤銷剛剛的普通 Commit，通常不應衝突。若看到 conflicted，先 `git status`，停止下一步。若要退出這次 Revert，在助教確認後使用：

```powershell
git revert --abort
```

若選擇解決：先另存衝突檔作備份，人工確認要保留的內容 → `git add -- task-status.txt` → `git revert --continue`。不要把 `<<<<<<<`、`=======`、`>>>>>>>` 當正常內容提交。不要對 Merge Commit 套本教材的 HEAD 撤銷範例。

## 中途關掉終端機怎麼辦

從自己的專案根目錄重新開 pwsh；用 status、branch、log、remote 確認進度。檔案、Commit 和 GitHub repo 都還在，不必從第一關重做。`$labAuthorPath` 等變數需重新設定，備份檔還在 `.lab-backups`。

## 檔案與憑證

不要使用會直接刪檔或重寫共享歷史的清理指令。需要移除本機檔案時，先在檔案總管移到垃圾桶；做不到就停止並詢問教師。不要為重做練習刪 `.git`，改用新的解壓縮副本與新 repo 名稱。

若意外提交密碼或 Token，停止推送並通知教師；若已推送，應立即到服務端撤銷／更換憑證，光做 Revert 不能把秘密從舊歷史消除。
