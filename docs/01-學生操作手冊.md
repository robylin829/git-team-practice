# 01｜從第一次 Commit 到 GitHub 合併

每個人都要做一遍。兩人一組，A 和 B 各自建立自己的儲存庫，之後交換審查。建議分成兩次課，共 150～180 分鐘；環境安裝另留時間。

主線：準備 → 建立本機歷史 → **建立 GitHub repo 並 Push** → 分支 → 修改 → 回復 → **PR／同儕 Review** → 合併 → Pull。

## 第 1 關｜建立你的第一個存檔點

**目的：**讓 Git 開始記錄這份教材；只影響這個專案，不修改全電腦的署名。
前置：已完成環境手冊，終端機位於教材根目錄，`Test-Path .git` 為 False。

```powershell
git init -b main
$labName = Read-Host '輸入你要顯示在 Commit 的暱稱'
$labEmail = Read-Host '貼上 GitHub Settings / Emails 中自己的 noreply 信箱'
git config user.name "$labName"
git config user.email "$labEmail"
git config --get user.name
git config --get user.email
git status
```

預期：分支為 `main`、尚無 Commit，教材檔案列為 Untracked（尚未追蹤）。署名不是登入密碼。

先讀內容，再把這份乾淨教材加入第一筆提交；這裡使用 `.` 是因為整份都是剛解壓縮的課程檔案。先確認沒有加進自己的私人檔案。

```powershell
Get-Content -LiteralPath task-status.txt
git add -- .
git diff --staged --stat
git diff --staged -- task-status.txt
git commit -m 'chore(lab): 建立小組任務板練習基準'
git log --oneline -1
git status
```

**驗收：**`task-status.txt` 為 todo，log 有一筆 Commit，status 顯示 `nothing to commit, working tree clean`。記下 SHA（前面的英數字）。每個人的 SHA 不同很正常。

**想一想：**`add` 是把這一刻的內容放進「待提交的籃子」，`commit` 才把籃子存成正式紀錄。

## 第 2 關｜真的把專案放到 GitHub

**目的：**在自己的 GitHub 建立私有儲存庫，並上傳第一筆歷史。
以下名稱在你的帳號下必須尚未使用；若已存在，輸入另一個名稱，例如 `git-team-practice-02`。不要覆蓋或刪掉原本的儲存庫。

```powershell
$labRepoName = Read-Host '輸入新儲存庫名稱，例如 git-team-practice-01'
gh repo create "$labRepoName" --private --source . --remote origin --push
git remote -v
git push -u origin main
gh repo view --web
```

第二次 Push 顯示 `Everything up-to-date` 正常；`-u` 幫 main 記住之後推送、拉取的對象。
`origin` 是遠端位址的暱稱，`main` 是分支名稱，不是資料夾。

**GitHub 驗收：**瀏覽器看到自己帳號底下的 repo、Private 標示、README 和 `task-status.txt`；點進檔案，值為 todo。記下儲存庫網址。從這關起，每位同學都必須有實際 GitHub 成果。

如果 CLI 建庫受限制：瀏覽器到 GitHub → `+` → New repository → 填新的名稱 → Private → **不要勾 README／.gitignore／License** → Create repository。複製 HTTPS 位址，再執行以下替代指令；此路徑僅在前面的 CLI 建庫未成功、`git remote -v` 沒有 origin 時使用。

```powershell
$labRemoteUrl = Read-Host '貼上剛建立空白儲存庫的 HTTPS 位址'
git remote add origin "$labRemoteUrl"
git push -u origin main
gh repo view --web
```

**現在先邀請同學**：依 [雙人協作手冊的第 1 節](02-雙人協作.md) 完成邀請與接受，避免最後才發現對方看不到私有庫。

## 第 3 關｜開一條分支，只處理一件事

**目的：**保留 main 為基準，在分支上補「狀態用語說明」。

```powershell
git switch -c feat/task-status
git branch --show-current
git status --short --branch
```

預期分支為 `feat/task-status`。`-c` 只在建立時使用；已建立後切換要用 `git switch feat/task-status`。

```powershell
@'
小組任務狀態共同定義
todo：還沒開始，例如尚未蒐集資料。
doing：正在處理，例如正在整理訪談。
done：已完成且經同學確認，例如簡報已校對。
統一使用以上三個英文小寫名稱，避免不同拼字造成誤會。
'@ | Set-Content -LiteralPath status-guide.txt -Encoding utf8
Get-Content -LiteralPath status-guide.txt
git status --short
git diff
```

預期 `?? status-guide.txt`；普通 diff 不會顯示這個未追蹤的新檔。這不是失敗。

```powershell
git add -- status-guide.txt
git diff --staged -- status-guide.txt
git commit -m 'docs(status): 統一狀態用語以避免小組成員誤解進度'
git show --stat HEAD
git status --short
```

**驗收：**此筆 Commit 只新增 status-guide.txt，工作目錄乾淨；訊息交代「為什麼」。這就是單一目的的 Atomic Commit。

## 第 4 關｜看懂工作目錄、暫存區與 Commit

**目的：**親眼看到 `add` 後再改檔案，不會自動更新暫存區。
這裡只改練習用 task-status.txt，稍後會先備份再還原。

```powershell
Set-Content -LiteralPath task-status.txt -Value 'doing' -Encoding utf8
git diff -- task-status.txt
git add -- task-status.txt
Set-Content -LiteralPath task-status.txt -Value 'BROKEN' -Encoding utf8
git status --short
git diff -- task-status.txt
git diff --staged -- task-status.txt
git show HEAD:task-status.txt
```

**驗收：**status 為 `MM`；工作檔是 BROKEN、暫存區是 doing、HEAD 是 todo。

| 位置 | 此刻的值 | 如何觀察 |
| --- | --- | --- |
| 工作目錄：你眼前編輯的檔案 | BROKEN | Get-Content、git diff |
| 暫存區：下一筆 Commit 的籃子 | doing | git diff --staged |
| HEAD：目前分支最新 Commit | todo | git show HEAD:task-status.txt |

先取消暫存，再保留備份，最後還原工作檔。不要在這裡 Commit。

```powershell
git restore --staged -- task-status.txt
Get-Content -LiteralPath task-status.txt
git diff --staged -- task-status.txt
New-Item -ItemType Directory -Path .lab-backups -Force | Out-Null
$labBackupPath = Join-Path '.lab-backups' ('stage-demo-' + [guid]::NewGuid().ToString('N') + '.txt')
Copy-Item -LiteralPath task-status.txt -Destination $labBackupPath
Write-Output "備份位置：$labBackupPath"
git restore -- task-status.txt
Get-Content -LiteralPath task-status.txt
git status --short
```

**驗收：**取消暫存後內容仍為 BROKEN、staged diff 無輸出；最後 restore 後為 todo、工作目錄乾淨。`.lab-backups` 被忽略，不會進 Commit；保留備份，不需要刪除。

## 第 5 關｜未提交的錯誤，用 restore 回復

**目的：**比較回復前後的 Commit SHA，證明沒有新增 Commit。

```powershell
$labBeforeRestore = git rev-parse HEAD
Set-Content -LiteralPath task-status.txt -Value 'BROKEN' -Encoding utf8
git diff -- task-status.txt
New-Item -ItemType Directory -Path .lab-backups -Force | Out-Null
$labRestoreBackup = Join-Path '.lab-backups' ('before-restore-' + [guid]::NewGuid().ToString('N') + '.txt')
Copy-Item -LiteralPath task-status.txt -Destination $labRestoreBackup
git restore -- task-status.txt
Get-Content -LiteralPath task-status.txt
git rev-parse HEAD
Write-Output "回復前：$labBeforeRestore"
git status --short
```

**驗收：**檔案回到 todo，回復前後 SHA 相同。`restore` 會覆寫未提交內容，不能當作一般備份工具；本例只還原自己刻意改壞且已備份的練習檔。

## 第 6 關｜已提交又已上傳的錯誤，用 revert 回復

**目的：**保留錯誤紀錄，新增一筆反向提交來修復，讓同學看得懂發生什麼事。
先確認目前在 `feat/task-status`，而且工作目錄乾淨。

```powershell
git branch --show-current
git status --short
Set-Content -LiteralPath task-status.txt -Value 'BROKEN' -Encoding utf8
git add -- task-status.txt
git diff --staged -- task-status.txt
git commit -m 'test(lab): 刻意提交未知狀態以練習回復已上傳錯誤'
git push -u origin feat/task-status
git log -1 --oneline
gh repo view --web
```

**到 GitHub 確認：**在頁面左上分支下拉選 `feat/task-status`，打開 task-status.txt，確實看到 BROKEN。main 仍是 todo。這一步不要跳過。

回到原終端機，先確認最新 Commit 正是剛剛的錯誤，再撤銷它；若你已額外提交其他內容，先停下請助教確認，不能直接照抄 HEAD。

```powershell
git log -1 --oneline
git revert --no-edit HEAD
git push
Get-Content -LiteralPath task-status.txt
git log -4 --oneline
git diff --check
$LASTEXITCODE
git status --short
```

**驗收：**狀態為 todo；log 看得到基準、狀態說明、錯誤、Revert 共四筆；diff --check 無輸出，緊接的退出碼為 0，status 無未提交變更。GitHub 分支上的檔案也回到 todo。

`--no-edit` 使用 Git 產生的 Revert 訊息，不需要學習終端機文字編輯器。Revert 不會抹去錯誤 Commit。

## 第 7 關｜驗證後建立 Pull Request

**目的：**提出可供同學閱讀的合併提案。Pull Request 不等於 git pull，也不會一建立就合併。

```powershell
Get-Content -LiteralPath task-status.txt
Get-Content -LiteralPath status-guide.txt
git diff main...HEAD
git diff --check main...HEAD
$LASTEXITCODE
git status --short
```

預期：todo；說明包含三種狀態；main 與目前分支最終差異只有 status-guide.txt（BROKEN 已被撤銷）；退出碼 0。main 此時仍是最初基準。

建立 PR 說明草稿。PR-DRAFT.md 被忽略，不會混入練習 Commit。只勾選自己已實際驗證的項目。

```powershell
@'
## 問題與結果
原本沒有共同狀態說明，小組可能用不同名稱表示進度。
新增 todo、doing、done 定義，並實測錯誤回復。

## 實際驗證
- [x] task-status.txt 最後為 todo。
- [x] status-guide.txt 定義三種狀態。
- [x] git log 保留 BROKEN 與 Revert 紀錄。
- [x] git diff --check main...HEAD 退出碼為 0。

## 範圍與風險
只做文字練習，尚未接入介面或資料庫。

## 請同學審查
請實際讀取分支檔案，確認三種狀態定義清楚並留下驗證結果。
'@ | Set-Content -LiteralPath PR-DRAFT.md -Encoding utf8
gh pr create --base main --head feat/task-status --title '統一小組狀態用語並驗證錯誤回復' --body-file PR-DRAFT.md
gh pr view feat/task-status --web
```

**GitHub 驗收：**看到 Open PR；base 是 main、compare 是 feat/task-status。閱讀 Commits 與 Files changed，貼上自己去除私人資訊的驗證截圖。從右側 Reviewers 選同學；如果無法指定，先檢查協作者邀請是否已接受。

接著兩人都執行 [雙人協作手冊](02-雙人協作.md)。**同學完成實際 Review 後，才繼續第 8 關。** 有修正需求時先依協作手冊提交修正並重新請對方確認。

## 第 8 關｜合併 PR，再同步回自己的電腦

**目的：**把已經審查的成果納入 main，並理解 GitHub 的 main 與本機 main 要同步。
先在 GitHub 檢查核准內容、Files changed 及合併資格。課程使用 **Create a merge commit** 保留四筆原始 Commit，儲存庫需允許此方式。

```powershell
gh pr view feat/task-status
gh pr merge feat/task-status --merge
git switch main
git pull --ff-only origin main
git status
Get-Content -LiteralPath task-status.txt
Get-Content -LiteralPath status-guide.txt
git log --oneline --graph --all -8
git rev-parse HEAD
```

也可在 GitHub 按 Merge pull request → 確認方式為 Create a merge commit → Confirm merge，再執行上面的 switch 與 pull。**CLI 和網頁合併二選一，不必做兩次。** 若畫面顯示規則阻擋或沒有此選項，請教師確認 repo 設定，不要用強制推送繞過規則。

**驗收：**GitHub PR 顯示 Merged；main 有狀態說明、task-status 為 todo；本機 main 已同步且工作目錄乾淨。正常情況有四筆練習 Commit 加一筆 Merge Commit；若有 Review 修正，筆數會增加。保留分支即可，不用按 Delete branch。

## 第 9 關｜把協作證據交出去

在 GitHub 點進各個 Commit 可複製完整網址／SHA；在 PR 的 Review 時間或留言時間可取得對應連結。依 [繳交表](../SUBMISSION.md) 填上 repo、PR、Review、SHA 與反思，透過課程平台繳交。私有 repo 需要依教師要求邀請教師為協作者。

可用以下指令再次檢查並在終端機截圖。若要存成檔案，只放到忽略的 `.lab-evidence`。

```powershell
New-Item -ItemType Directory -Path .lab-evidence -Force | Out-Null
git log --oneline --graph --all -10 | Out-File -LiteralPath .lab-evidence/history.txt -Encoding utf8
git status | Out-File -LiteralPath .lab-evidence/final-status.txt -Encoding utf8
gh pr view feat/task-status --json url,state,mergedAt
```

完成標準：你有一個合併後的 PR，且在另一位同學的 PR 留下有理由的 Review。只有本機指令截圖或空白 GitHub repo 不算完成。
